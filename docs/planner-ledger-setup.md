# 个人记账

“日程 / 纪念日 / 记账”共用现有登录，每个用户可以建立多张自己的银行卡、现金和电子钱包。账户不是其他用户账号，各用户的数据由 RLS 隔离。

使用时先点“添加账户”，填写名称、币种和初始金额。人民币（CNY / RMB）、英镑（GBP）、新加坡元（SGD）分别记账和统计，不换汇相加。初始金额可以为负，不计入月收入。

“记一笔”默认支出，只填金额即可保存。尚未选择账户的流水立即计入对应月份开销，之后点“待分配账户”补选同币种银行卡；分配或更换账户只改变余额，不会重复增加月支出。余额为初始金额加已分配收入减已分配支出。账户有流水或固定规则引用后不能删除或更换币种；可以修改名称、初始金额和流水。

固定收支可选择收入/支出、金额、账户、每月几号、起止月份。31 日遇小月按月末生成。已到期月份会补记，每条规则每月最多一笔；暂停期间不生成，重新启用后会补记起止范围内的到期月份。修改规则只影响尚未生成的月份。删除规则保留历史，删除已生成的一笔也不会重新生成。这里只生成记账记录，不连接银行或实际扣款。

月度卡片显示三种货币各自的收入、支出、结余，可切月份、按账户筛选、搜索用途和备注。初始余额不计入月度收支。导出备份包含全部月份的账户、固定规则和流水（包含作废标记），保留历史信息。

## 部署

1. 已有 `supabase/planner.sql` 和登录功能后，执行 CLI 生成的 `supabase/migrations/20261015210858_planner_personal_ledger.sql` 一次。
2. 项目启用 Supabase Cron（`pg_cron`）时，该迁移创建 `planner-ledger-daily`，UTC 16:05，即 UTC+8 次日凌晨 00:05 执行。网页关闭也会生成；登录和同步时的 RPC 会补记漏掉的到期月份。
3. 未安装 Cron 的项目先在 Supabase 启用 Cron，再单独执行：

```sql
select cron.schedule('planner-ledger-daily', '5 16 * * *',
  $$select planner_ledger_private.post_due(null,
      (clock_timestamp() at time zone 'Asia/Singapore')::date);$$);
```

4. 发布网页代码。无需浏览器额外密钥，沿用已有 Supabase publishable key。

新表均启用 RLS，余额/月度汇总视图使用 `security_invoker`。账户复合外键同时校验用户和币种。单笔金额以整数分存储，汇总以字符串传给浏览器再用 BigInt 显示。固定流水的规则和月份不可由客户端伪造或修改，数据库唯一约束保证重复同步不重记。生成函数在非公开 schema，仅受限的当前用户入口可由登录用户调用，批量入口只供数据库任务使用。
