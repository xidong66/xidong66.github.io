# 习惯打卡

在“日程 / 纪念日 / 记账 / 打卡”的第四个页签，点击“新建习惯”，填写名称、开始日期、卡片颜色和每日目标或备注。每个习惯每天打卡一次，单独显示月历；同一账号在手机电脑上同步，各账号记录相互隔离。

- 点击“今天打卡”完成当天，已完成时再次点击可取消。
- 点击月历里的过去日期可补打，再点击取消。开始日之前、未来日期和相邻月份的占位格不能操作。
- 顶部可切换月份，所有习惯同时显示该月，方便比较。月历从周日开始。
- 本月打卡：所选月份实际打卡天数；累计打卡：所有月份实际打卡天数。
- 月完成率：该月打卡天数 / 从习惯开始日起至该月末或今天（取较早）的天数。未来日期不计入分母；该月还没开始习惯时为 0%。
- 当前连续：从今天（如已打卡）或昨天往前累计的连续打卡天数。今天尚未结束时不会提前打断昨天的连续记录。它反映当前连续情况，不随正在查看的历史月份改变。
- 可修改名称、颜色、备注与开始日期；开始日不能移到已有打卡记录之后，避免隐藏历史。
- 删除习惯会在确认后同时删除它的打卡记录。取消删除会保留全部记录。
- “导出备份”格式版本 4 含完整习惯及所有月份打卡记录；数据分批读取，每批 500 条，防止长时间使用后统计或备份遗漏。

## 部署

在已有基础日程数据库的项目上执行一次 `supabase/migrations/20261016094310_planner_habits.sql`，然后发布网页。不需要新密钥、外部服务或定时任务。

新增的 `planner_habits` 和 `planner_habit_checkins` 均开启 RLS，仅登录用户可操作自己名下记录。复合外键同时验证习惯和用户归属；唯一约束保证每个习惯每天最多一条。打卡记录不可 UPDATE，只允许添加、取消。数据库按 UTC+8 拒绝未来打卡，并验证开始日。习惯更新通过 `updated_at` 条件防止覆盖其他设备的修改，取消打卡以原记录 ID 和创建时间为条件，避免删除其他设备重新打上的记录。

两张表加入已有 Realtime publication，沿用可见页面每 30 秒同步、重新聚焦同步和手动刷新。离线不接收写入；同步失败保留上次加载的卡片并明确提示。
